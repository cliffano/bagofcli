    • bagofcli

    A bag of utility functions for building command-line tools: command and option parsing backed by [commander](https://www.npmjs.com/package/commander), child process execution, process exit handling, file and configuration lookup, and coloured console logging.
    Source:

    Example
    import bag from "bagofcli";

const actions = {
  commands: {
    hello: {
      action: function (command) {
        console.log("Hello %s", command.args[0]);
      },
    },
  },
};
bag.command(import.meta.dirname, actions);

    (static) command(base, actionsopt, optsopt) → {void}

    Parse command line arguments and execute actions based on the specified commands. Uses commander to provide `-V` / `--version` flags to display the version number, and `-h` / `--help` flags to display the help info. Commands, their positional arguments, and the global and command options are declared in the command file, while `actions` provides the action handler of each command. A command without declared args accepts any positional arguments by default, a command declared with `allowExcessArguments: false` rejects unexpected ones while parsing, before the action handler is called, and the process exits with status code 1. An option declared with `choices` only accepts one of the listed values, commander rejects any other value while parsing, before the action handler is called, and the process exits with status code 1. Likewise, an option declared with `min`, `max`, or `integer` only accepts a number (or an integer when `integer` is true) within the inclusive range. Arguments and options are validated against the rules declared in the command file before the action handler is called, the process exits with status code 1 without calling the action handler when any of them is invalid.

    (static) exec(command, fallthrough, cb) → {void}

    Execute a one-liner command. The output emitted on stderr and stdout of the child process will be written to process.stdout and process.stderr of this process. Fallthrough is handy in situation where there are multiple execs running in sequence/parallel, and they all have to be executed regardless of success/error on either one of them.

    (static) exit(erropt, nullable) → {void}

    Handle process exit based on the existence of error. This is handy for command-line tools to use as the final callback. Exit status code 1 indicates an error, exit status code 0 indicates a success. Error message will be logged to the console. This function can be used as a standard `cb(err, result)` callback, the result is not declared in the signature because it is not used, the process simply exits with status code 0 when there is no error.

    (static) lookupConfig(keys, opts, cb) → {void}

    Lookup config values for the specified keys in the following order: - environment variable - if optional file is specified, then check for the value inside the file, the file type is determined by the file extension (.json, .yaml, or .yml) - if optional prompt is set to true, then prompt the user for the config values that are not found in the environment variable and the file the value typed in by the user is masked when the key contains the word password (case insensitive) The file is located using module:bagofcli.lookupFile.

    Actions

    Action handlers for commands in the form `{ commands: { : { action: function (command) {} } } }`. The command name is mapped to the command name specified in the command file. Each action handler is called with a module:bagofcli~CommandArg. The TypeScript type is defined in types.d.ts.

    CommandArg

    Object passed to a command action handler, with these properties: - `args` (`Array`): positional arguments, in the order they were passed in - `name` (`Function`): function that returns the name of the invoked command Besides those, every parsed option is available as a direct property keyed by the option's long flag in camel case (e.g. `--some-opt ` is available as `someOpt`). This covers both the command's own options and the global options. When a global option and a command option share the same name, the global option value takes precedence. The TypeScript type is defined in types.d.ts.
